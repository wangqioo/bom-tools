# 2026-04-24 规则逻辑 Review 记录

## Review 范围

本轮重点审核 `pstx_analyzer.py` 中会影响业务判断可信度的规则逻辑，而不是语法、UI 样式或普通代码风格。已逐段检查：

- 电压网络识别与电容降额。
- AC 耦合候选识别。
- 电阻值解析、上拉/下拉、串阻与隔串阻上下拉。
- OD/OC 候选缺上拉识别。
- 芯片 pin 电阻状态表。
- DEPOP 默认排除边界。
- 页码在规则输出中的真实页使用。

## 已确认并修复的问题

### 1. 电阻值文本单位解析漏判

- 问题：`_parse_ohms()` 旧逻辑先替换 `OHM` 再替换 `OHMS`，`10OHMS` 会变成 `10RS`，`10KOHM` 也无法稳定折算。
- 影响：串阻、上拉、下拉的阻值会被当成缺失，后续分压风险只能输出“无法计算”。
- 修复：统一处理 `OHMS?/Ω/欧` 后缀，并把 `K/M/G + R` 归一到 K/M/G 单位。
- 覆盖测试：`test_parse_ohms_supports_ohm_word_suffixes`。

### 2. 多级串阻多路径漏判

- 问题：`_walk_series_paths()` 使用全局 visited。菱形拓扑中，两条独立串阻链到达同一个远端上拉时，第二条会被剪掉。
- 影响：芯片 pin 的隔串阻上拉数量、串阻分压风险都会少报。
- 修复：改为路径本地防环，按完整路径签名去重，同时增加最大跳数和最大结果数保护。
- 覆盖测试：`test_analyze_resistors_keeps_parallel_series_paths_to_same_remote_pullup`。

## 已检查但本轮保持保守的规则

- 电压推断：仍只接受首 token 的明确电压/电源名或用户自定义映射，不从 `PG_P1V8` 这类信号名中提取电压。
- AC 耦合：仍要求差分 P/N 成对且电容镜像成对出现，单独 `_N` 或单颗电容不升级为 AC 耦合。
- OD/OC：仍只输出候选缺上拉，不把 `ALERT/FAULT/INT` 等弱线索单独当成强结论。
- DEPOP：默认从后续规则分析中排除，但 BOM_OPTION 明细仍保留原始器件用于审查。
- 页码输出：规则结果继续使用真实页，不回退显示逻辑页。

## 后续需要样本再判断的点

- 全局 12V/50V 电容直通规则目前依赖可识别的整板最大正电压。若真实项目里存在大量 `12V_EN`、`3V3_PG` 这类信号且会影响全局最大电压，需要再加“电源 token 黑名单/白名单”或结合器件连接关系。
- 电源网络识别目前偏保守，可能漏掉 `USB_VBUS`、`SYS_3V3` 这类非首 token 电源名。本轮不放宽，避免重新引入 `PG_P1V8` 误判。
- OD/OC 真正可靠判断需要器件 pin 类型库或芯片模型；当前只能作为候选提示。
