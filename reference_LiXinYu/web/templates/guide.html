快速使用流程

建议按“缓存数据先同步、项目再分析、结果再对比或问 Agent”的顺序使用。

  1. 1
    同步飞书优选库 ?

    如果报告需要做料号、规格、PI、选型顺序校对，先进入“飞书同步”页把固定表同步到本地缓存。

  2. 2
    创建项目分析任务 ?

    在首页输入 Cadence DEHDL 项目根路径，生成结构化报告和可查询的本地 run 数据。

  3. 3
    查看报告与规则表格 ?

    先看概览，再展开 BOM、网络、DRC、电阻、降额、CSA、飞书校对等分区。

  4. 4
    用 Agent 追问或进入项目对比 ?

    报告页和对比页右下角都保留连续对话浮窗；对比两个 run 时进入独立项目对比工作台。

DATA SOURCES

数据来源与页码口径

系统不会凭空判断，所有规则都尽量挂到可复核的数据源。

Cadence / PSTX 输入

  • packaged/pstxprt.dat：元件属性、位号、料号、值、P_PATH、split symbol section 信息。
  • packaged/pstxnet.dat：网络、节点、Pin/Net 拓扑关系。
  • packaged/pstxref.dat：可选交叉引用信息，用于补充定位。
  • sch_1/page*.csv：PAGE_NUMBER、页属性和部分文本证据。
  • sch_1/page*.csa：画圈、线段、DOT、文本、几何对象与页级语义对比。

页码 ?

  • module_order.dat / module_order 用于把子模块内部页映射到用户在总体工程中看到的页。
  • 非子模块元件一般直接使用自身页码，不额外暴露“子模块映射页”概念。
  • Agent 回答“第 1-30 页”时，也按页码理解，并读取对应 sch_1/pageX.csv|csa。

FEATURE LOGIC

功能逻辑总览

下面是每个主要功能的实现口径，鼠标停在问号上可以看更具体边界。

BOM / DEPOP ?

按位号、料号、值、BOM_OPTION 汇总元件，支持贴装 BOM 和总 BOM 视图。

DRC / 网络命名 ?

检查未命名网络、网络节点、页码定位和潜在命名类风险。

电阻拓扑 ?

识别串联电阻、上下拉候选、芯片 Pin 偏置状态和单端候选网络。

电容降额 ?

按电容耐压、网络电压、差分耦合特例和人工复核边界输出风险。

CSA 几何 ?

保留几何规则和页级语义比对能力，不再展示低价值的独立画圈对象清单。

飞书校对 ?

用本地缓存的 HQ 料号匹配规格、PI、选型顺序和用户确认的扩展字段。

全模块判定细则

每张卡片都按“输入、判定步骤、输出与边界”解释，方便你从报告结果反查系统为什么这么判。

数据读取与预处理 ?

输入

  • pstxprt.dat：元件属性、HQ_CODE、VALUE、P_PATH、SECTION_NUMBER。
  • pstxnet.dat：网络节点、位号、引脚和 Pin/Net 拓扑。
  • page*.csv、page*.csa、module_order.dat：页面与图形证据。

判定步骤

  • 先归一化位号、网络名、电阻值、电容耐压、BOM_OPTION 和页码。
  • 同一位号的 split symbol 合并为一个元件，但保留多个 section 证据。
  • DEPOP/DNP 在贴装类结果中按规则排除；拓扑类复核保留原始连接防止误判。

输出与边界

  • 报告只展示可复核摘要，完整证据保留在本地 run、trace 或 detail 工具中。
  • 读取失败、字段缺失、路径缺失会转成“无法判断/需人工复核”，不硬猜。

页码与原理图总页数 ?

输入

  • 主模块页、P_PATH 中的子模块本地页。
  • module_order.dat 的子模块起始页、页数和映射范围。
  • page_rows 只表示有记录或有元件的页码，不表示工程总页数。

判定步骤

  • 页码 = 子模块起始页 + 子模块内部页 - 1。
  • 非子模块或缺映射时，兜底为主模块解析出的页码。
  • 原理图总页数优先解析 module_order(.dat) 最后一条映射，并加上子模块页数 - 1。

输出与边界

  • 报告、查询、对比和 Agent prompt 统一说“页码”。
  • 尾部空白页不会被 page_rows 捕获，因此不能用 page_rows 唯一页数回答总页数。

位号归一与关键器件分类

输入

  • 位号、CDS_LIB、CDS_PART_NAME、VALUE、HQ_CODE、封装和值。
  • Pin/Net 节点、飞书缓存匹配和规格书候选。

判定步骤

  • U/PU/XU/IC/连接器类进入关键器件；R/C/L 进入无源件。
  • PC16A10、PR10A1、PL2A5 会按 power 前缀 + 子模块后缀归回 C/R/L。
  • DFMEA 准备阶段会进一步按料号、规格、Pin/Net 和飞书信息生成元件身份卡。

输出与边界

  • 不确定类别标记为 unknown/needs_context，不强行猜芯片类型。
  • 项目对比中关键器件和无源件分开比较，避免 R/C/L 误入关键器件差异。

Split symbol 大芯片

输入

  • PART_NAME U46 ... 顶层块。
  • 多个 SECTION_NUMBER 下的 C_PATH、P_PATH、PHYS_PAGE、XY、LOCATION、HQ_CODE。

判定步骤

  • 按相同 LOCATION/位号合并 section，而不是把每个 symbol 当独立芯片。
  • 聚合多个页码、主模块页、XY 和 section 号。
  • HQ 料号优先取 section 的 HQ_CODE，缺失时从 CDS_PART_NAME / PART_NAME 中提取 HQ 字段兜底。

输出与边界

  • 查询 U46 时可能返回多个页面，这属于正常 split symbol 表达。
  • Pin/Net 和项目对比按同一芯片位号聚合，不因 section 分裂而漏料号。

BOM / DEPOP / BOM_OPTION 拼写 ?

输入

  • 位号、HQ_CODE、VALUE、BOM_OPTION、封装、页码。
  • 首页 DEPOP 参与排查开关和总 BOM 视图开关。

判定步骤

  • 常规贴装 BOM 排除 DEPOP/DNP；总 BOM 额外展示贴装 + DEPOP/DNP 汇总。
  • 合法 BOM_OPTION 包含空值、DEPOP、OPTION、MAIN_PLD、MAIN、ALT、DNP。
  • 未知值或接近合法值的拼写会输出“疑似 typo/需人工确认”。

输出与边界

  • 不会自动修正 BOM_OPTION，只提示风险和候选解释。
  • 测试点等特殊元件会按当前规则从部分属性检查中排除。

网络分类、差分对与未命名网络页码 ?

输入

  • 网络名、节点列表、连接元件位号和 pin 名。
  • 元件页码，用于反查网络出现位置。

判定步骤

  • 电源/地通过网络 token 和别名归一，AGND/GNDA/VSS/0V 作为地类终止点。
  • 差分对通过 P/N、+/- 等命名关系识别，用于降额和风险解释。
  • 未命名网络匹配 UNNAMED_，并从连接节点反查页码集合。

输出与边界

  • 未命名网络会展示端点和页码，方便回到原理图定位。
  • 命名不规范但不满足规则时，保守进入人工复核，不硬判为错误。

DRC 属性完整性与单端候选

输入

  • 元件 HQ_CODE、VALUE、封装、BOM_OPTION、位置页码。
  • 网络节点数量、端点列表和元件类型。

判定步骤

  • 缺 HQ、缺值、缺封装按属性完整性问题输出；TESTPOINT 类按规则跳过部分属性检查。
  • 电压、电流、功耗等属性出现 TBD 时标记中风险复核。
  • 单端候选看完整网络拓扑，排除测试点和未命名网络噪声，必要时考虑 DEPOP 电阻连接。

输出与边界

  • 属性缺失是确定性检查，但设计是否允许空值仍需项目规范确认。
  • 单端候选是“可能悬空/需复核”，不是自动判定设计错误。

上下拉判定 ?

输入

  • 电阻元件两端网络、阻值、BOM_OPTION、页码。
  • 目标信号连接的芯片 Pin、网络命名和上下文。

判定步骤

  • 电阻一端连接普通信号，另一端连接电源网时，记录为上拉候选。
  • 电阻一端连接普通信号，另一端连接地类网时，记录为下拉候选。
  • 同一信号存在多个上拉/下拉时，输出重复偏置候选和阻值证据。

输出与边界

  • 直接上下拉会进入电阻检查和芯片 Pin 状态解释。
  • 是否合理取决于芯片管脚功能，工具只负责把拓扑证据找出来。

串阻判定逻辑、隔串阻上下拉与分压风险 ?

输入

  • 电阻阻值，支持 R/K/M/G、OHM/OHMS、Ω、欧和 4K7 等常见写法。
  • 每个电阻的两个唯一连接网络，以及网络是否 power/gnd/signal。
  • 直接上下拉结果、芯片 Pin 端点和 DEPOP 原始拓扑。

判定步骤

  • 电阻两端都是普通信号网时，建立串阻边；接 power/gnd 的电阻不作为串阻边。
  • 从芯片 Pin 所在信号开始，沿串阻图搜索最多 8 跳，路径内防环但允许多条独立路径到同一远端。
  • 若远端存在直接上拉/下拉，则形成隔串阻上下拉候选；计算串阻总阻值、远端偏置阻值和比例。
  • 分压风险规则：偏置阻值很小且串阻占比明显、或串阻/偏置比例超过阈值时，标记高风险或 warning。

输出与边界

  • 输出串阻链、经过网络、总串阻、远端上下拉、页码和风险等级。
  • DEPOP/DNP 电阻在常规串阻报告可排除，但单端候选和拓扑连通性会考虑原始连接，避免误报断路。
  • 工具不会判断芯片内部是否允许该偏置，只提示“这条路径值得复核”。

芯片 Pin 电阻状态表

输入

  • 芯片 Pin 网络、直接上下拉、隔串阻上下拉、串阻网络和芯片连接数量。
  • 网络与元件页码、飞书 HQ 校对信息、BOM_OPTION/DEPOP 状态。

判定步骤

  • 对每个芯片 Pin 汇总直接上下拉、隔串阻上下拉和串阻另一端网络。
  • 按页码、子模块和飞书信息辅助定位，不再凭 OD/OC、ALERT、INT 等命名猜测是否缺上拉。
  • 需要判断开漏/开集上拉时，应结合 datasheet pin type 或设计约束单独确认。

输出与边界

  • 芯片 Pin 表优先服务定位和证据聚合，不替代人工读原理图。
  • 工具不再输出命名猜测类缺上拉结论，避免命名线索造成误判。

电容降额判定 ?

输入

  • 电容 VALUE/额定耐压、两端网络、网络电压推断、页码。
  • 差分对识别结果和 GND/0V 等地网识别结果。

判定步骤

  • 缺额定耐压或无法推断电压时输出无法判断。
  • 若全局低压场景且电容额定 50V 及以上，按低风险通过。
  • 若两端都是差分对且同极性，标记为 AC 耦合电容，按低风险通过。
  • 其他场景按最大工作电压 / 额定耐压计算使用比例，与默认阈值比较。

输出与边界

  • 输出通过、失败、低风险通过或无法判断，并说明电压来源置信度。
  • 低风险通过不等于无需设计确认，只代表当前规则侧未发现高风险证据。

BOM_OPTION 打圈覆盖

输入

  • BOM_OPTION/DEPOP/DNP 元件、XY 坐标、页码。
  • 主模块或子模块对应 sch_1/pageX.csa 中的 CIRCLE/ARC/几何对象。

判定步骤

  • 主模块元件直接在当前工程对应页查圆圈覆盖。
  • 子模块元件先从 module_order.dat 找子模块名，再按 P_PATH 中的本地页进入同级 worklib 子模块工程检查。
  • 用元件中心和画圈中心/半径的几何关系判断已打圈、疑似打圈、未打圈或无法判断。

输出与边界

  • 报告最终仍只展示该元件在页码对应位置是否打圈。
  • 缺 XY、缺 CSA、缺子模块路径时输出无法判断，不把缺证据当未打圈。

CSA 几何规范与页级 Cadence 语义比对

输入

  • pageX.csa 中的 WIRE、DOT、CIRCLE、ARC、FORCEPROP SIG_NAME、文本和未知对象。
  • pageX.csv 中的 PAGE_NUMBER 和关键属性行。

判定步骤

  • DOT/WIRE 建立连接组件，记录 bbox、线段、junction/dot、信号标注和 fingerprint。
  • 未知 CSA 行不会丢弃，会进入 UnknownGraphicObject 并参与 raw fingerprint 比对。
  • 项目对比中“第 1-30 页”按页码读取 A/B 两侧 pageX.csv|csa 做语义差异。

输出与边界

  • 输出对象新增/删除/移动、拓扑变化、信号名变化、属性变化和原始兜底差异。
  • 独立 CSA 画圈对象表已删除；底层圆圈解析仍服务 BOM_OPTION 打圈。

飞书在线同步与飞书 HQ 校对 ?

输入

  • 企业网关 spreadsheetsMetainfo 返回的 sheetId、title、rowCount、columnCount。
  • getSheetsValue 返回的 valueRange.values，rich cell 会归一化为文本。
  • 用户确认的 HQ料号、规格型号 / Part Number、PI、选型顺序和扩展字段。

判定步骤

  • 跳过 blockInfo 非表格块，按返回 range 对齐行列，A 列为空也不移动后续列。
  • 每个 Sheet 独立识别表头，不携带其他 Sheet 的上下文或旧 mapping。
  • 同步后按 HQ 料号写入本地 SQLite 缓存，报告按 Cadence HQ_CODE 与缓存 hq_no 只读匹配。

输出与边界

  • 飞书规格、PI、选型顺序自然内联到 BOM、芯片 Pin 和项目对比原有表格。
  • Agent 只能辅助推荐表头 title 和扩展字段候选，不能替用户确认字段映射或直接写库。

项目对比规则

输入

  • A/B 两个已分析 run 的 report、bundle、飞书 HQ 校对结果和可选原始项目文件。
  • 关键器件、无源件、网络、Pin/Net、报告检查表和页级 Cadence 语义工具。

判定步骤

  • 先看关键器件新增/删除，再按位号比对每个芯片/连接器的 Pin-Net、引脚名、页码和飞书信息。
  • R/C/L 单独保留 Pin-Net 变化，不与关键器件混在一起。
  • 网络连接按节点变化、网络新增删除和元件属性变化分区展示。

输出与边界

  • 独立 `/compare` 页面按需懒加载宽表，避免一次性渲染全部数据卡顿。
  • Compare Agent 会重建服务端对比 payload，不信任前端传入的大型摘要。

DFMEA 准备度、规格书与 ref_checklist

输入

  • 元件身份卡：位号、类别、HQ 料号、规格、PI、选型顺序、Pin/Net、飞书匹配。
  • PSTX_DATASHEET_DIR 本地 PDF 规格书索引。
  • ref_checklist/ 中的真实 review 问题、Excel 记录和 changelist。

判定步骤

  • 先判断哪些芯片/连接器具备 DFMEA 输入条件，哪些缺规格、PI、芯片类别或关键网络。
  • 规格书只做文本型 PDF 页级检索和片段引用；扫描版或加密 PDF 标记需人工处理。
  • ref_checklist 只作为历史问题模式参考，必须同时引用当前项目 evidence 才能形成建议。

输出与边界

  • 当前只输出 DFMEA 准备度、证据缺口和用户补充问题，不生成正式 DFMEA 表。
  • 历史 checklist 命中不等于当前项目已发生问题，必须二次取当前项目证据。

Agent 证据压缩不替代原始证据

输入

  • 用户问题、profile/auto capability plan、playbook、tool_result_contract 和本地 trace。
  • 工具返回的三层证据：摘要层、证据卡层、原始层，以及 detail_tool / aggregation_tool。

判定步骤

  • 摘要层给模型快速规划，避免 80k 窗口被大表或 PDF/CSA 原文塞满。
  • 证据卡层保留 evidence id、来源表、行号、页码、位号、网络、字段名、命中原因和 detail_tool。
  • 原始层完整保存在本地 trace/store；完整表格行、PDF 片段、CSA/CSV 原始片段需要时通过 detail 工具继续读取，并可在 UI 展开。
  • 当结果是 preview/partial/truncated 时，Agent 必须优先用聚合工具或详情工具继续取证。

输出与边界

  • 证据压缩是“给模型节流”，不是丢弃证据；用户可通过 Trace 抽屉查看证据卡和原始工具结果。
  • 模型不能写文件、不能直接操作飞书、不能把历史经验当当前项目结论。

AGENT / HARNESS

Agent 与 Harness 如何工作

Agent 不是直接读写项目的脚本执行器，而是受控的本地只读取证框架。

1. 理解问题

本地 planner/playbook 先判断问题涉及报告、飞书、对比、页级语义或 DFMEA 准备。

2. 选择工具

优先选择批量工具和聚合工具，避免一条一条循环或把截断 preview 当完整数据。

3. 三层证据

模型默认接收摘要层和证据卡层；原始层留在 trace/store，用户可展开，模型需通过 detail_tool 二次读取。

4. 多轮澄清

缺规格、PI、芯片类别或用户上下文时，浮窗会要求补充信息后继续同一任务。

安全边界： Aster 只作为模型接口；工具执行、路径白名单、schema 校验、轮数限制和 trace 都由本地 harness 控制。 第一版不写 PSTX、不改 Cadence 项目、不自动同步飞书、不自动生成正式 DFMEA 风险结论。

MANUAL REVIEW

需要人工复核的边界

工具会尽量给证据，但下面这些情况不应该让模型硬下结论。

证据不足

  • 飞书缓存缺少 HQ 料号或字段映射未确认。
  • 规格书 PDF 未配置、扫描版不可抽取、或匹配到多个候选。
  • CSA 出现未知对象，当前只能按 raw/fingerprint 追溯。
  • module_order 缺失或子模块路径无法定位。

建议复核

  • 所有“候选”类结果都应结合原理图上下文确认。
  • 降额低风险通过不等于无需设计确认，只代表规则侧未发现高风险证据。
  • Agent 回答必须引用当前项目 evidence；历史经验和飞书缓存不能替代当前项目证据。
  • 项目对比的大表会懒加载，完整统计应优先走聚合工具或后端 compare API。
