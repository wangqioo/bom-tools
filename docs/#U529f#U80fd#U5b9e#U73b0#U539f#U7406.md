## 1 文件解析

### 1.1 pstxprt.dat 格式与解析

`pstxprt.dat` 是 Cadence Packager-XL 输出的元件属性文件，格式为文本块结构：

```
PART_NAME
C1 'CAP_HDL'
 HQ_CODE = 'HQCAP001'
 VALUE = '100nF'
 PACKAGE = '0402'
 VOLTAGE = '10V'
 DRAWING = 'PAGE2_BLOCK3'
```

**关键处理步骤：**

**（1）续行处理**：Cadence 文件中长属性值会用 `~` 续行，解析前需先将所有续行拼接：

```python
if line.rstrip().endswith('~'):
    buf += line.rstrip()[:-1]   # 去掉 ~ 继续拼接
else:
    buf += line
    result.append(buf)
    buf = ''
```

**（2）按 `PART_NAME` 分块**：用 `re.split(r'\nPART_NAME\n', text)` 将文件切分为每个元件的数据块。

**（3）属性提取**：用正则从每个块中提取所有 `KEY = 'VALUE'` 格式的属性：

```python
re.finditer(r"\b([A-Z][A-Z0-9_]*)\s*=\s*'([^']*)'", block)
```

采用"先到先得"策略，同一属性名只取第一个值，防止重复定义覆盖。

### 1.2 pstxnet.dat 格式与解析

`pstxnet.dat` 描述网络连接关系：

```
NET_NAME
'P3V3'
 NODE_NAME C1 1
  'VCC' :
 NODE_NAME U3 4
  'VDD' :
```

**解析逻辑：**

- 按 `NET_NAME` 分块
- 用 `NODE_NAME\s+(\S+)\s+(\S+)` 提取每个节点的 `refdes` 和引脚号
- 在节点后的 200 字符内用 `'([^']+)'\s*:` 提取引脚名称（pin name）

### 1.3 数据整合

解析完两个文件后，建立 `comp_nets` 反向索引：

```
comp_nets[refdes][pin] = net_name
```

再将 `nets` 字典写入每个 `comp` 对象的 `'nets'` 字段，使每个元件能直接查到自己的全部连接关系。

## 2 元件类型识别

类型识别采用**两级降级策略**：

**第一级：部件名关键词匹配**

对 `part_name`（小写）做字符串包含检查，优先级从上到下：

```python
[(['cap_pol'],              'CAP_POL'),
 (['cap_hdl', 'cap_'],      'CAP'),
 (['res_hdl', 'res_'],      'RES'),
 (['mosfet', 'nmos', 'pmos'], 'FET'),
 (['bjt', 'npn', 'pnp'],   'BJT'),
 ...]
```

**第二级：位号前缀匹配**

若第一级未命中，从位号提取字母前缀（`re.match(r'[A-Za-z]+', refdes)`）后查表：

```python
{'C': 'CAP', 'R': 'RES', 'L': 'IND', 'U': 'IC',
 'Q': 'FET', 'D': 'DIODE', 'J': 'CONN', 'Y': 'XTAL', ...}
```

无法识别的默认为 `'IC'`。

## 3 BOM 构建与合并

### 3.1 分类

遍历所有元件，按 `BOM_OPTION` 属性分为两类：

- `bom_option == 'DEPOP'`：进入 DEPOP 列表
- 其他（含空值）：进入贴装列表

### 3.2 合并 BOM

按 `料号`（或 `描述` 字段）作为合并键，将相同物料的元件聚合为一行：

```python
key = comp['hq_code'] or comp['part_name']
groups[key]['位号列表'].append(refdes)
groups[key]['数量'] += 1
```

**排序**：按类型优先（CAP < CAP_POL < RES < IND < IC < …）再按料号字母序，确保输出 BOM 按类型分组排列。

## 4 网络拓扑分析

### 4.1 电源/GND 网络识别

基于正则表达式匹配网络名：

```python
GND 网络：re.search(r'GND|AGND|SGND|PGND|DGND', net_name)
电源网络：re.search(r'^P\d|^[0-9]+V|VCC|VDD|VBAT|VCORE|PVDD|AVDD|DVDD', net_name)
          且不在 GND 网络中
```

### 4.2 差分对识别

枚举常见差分对后缀组合，对每个网络名检查是否能找到配对：

```python
suffix_pairs = [
    ('_P', '_N'), ('_DP', '_DN'), ('.P', '.N'),
    ('_TXPLUS', '_TXMINUS'), ('_RXPLUS', '_RXMINUS')
]
```

若 `NET_A_P` 和 `NET_A_N` 同时存在，则识别为差分对 `NET_A`。

### 4.3 单端网络

`len(nodes) == 1` 的网络，表示只有一个引脚连接到这个网络，**疑似漏连**。测试点和 UNNAMED 网络除外。

## 5 DRC 设计检查

### 5.1 缺属性检查

直接判断属性字段是否为空字符串，测试点（TESTPOINT 类型）跳过：

```python
if not comp.get('hq_code'):  → 缺料号
if not comp.get('value'):    → 缺 VALUE
if not comp.get('package'):  → 缺封装
```

### 5.2 TBD 属性检查

对 `VOLTAGE`、`CURRENT`、`POWER` 三个属性，检查是否包含 `TBD`（大小写不敏感）：

```python
if 'TBD' in val.upper()
```

### 5.3 BOM_OPTION 拼写风险检测

**算法：Levenshtein 编辑距离**

编辑距离定义：将字符串 A 变为字符串 B 所需的最少「单字符插入/删除/替换」操作次数。

实现采用标准动态规划（二维 DP 压缩为一维滚动数组）：

```python
dp = list(range(len(b) + 1))
for i, ca in enumerate(a):
    prev = dp[:]
    dp[0] = i + 1
    for j, cb in enumerate(b):
        dp[j+1] = min(
            prev[j] + (0 if ca == cb else 1),  # 替换
            dp[j] + 1,                           # 插入
            prev[j+1] + 1                        # 删除
        )
```

**判断逻辑：**

- 在白名单（`DEPOP/OPTION/MAIN/ALT/DNP/...`）内：`✅ 合法`
- 与最近合法值编辑距离 ≤ 2：`❌ 疑似拼错`
- 距离 > 2：`⚠ 未知值`

典型例子：`DEPO → DEPOP`（距离 1）、`OPTIOB → OPTION`（距离 1）。

## 6 电容降额分析

### 6.1 工作电压推断

**基于网络名正则匹配**，内置 30+ 条规则，例如：

```python
(r'P3V3',        3.3),
(r'\b3V3',       3.3),
(r'P1V8',        1.8),
(r'P5V(?!\d)',   5.0),   # 负向预查：P5V后不接数字，避免误匹配P5V0
(r'GND',         0.0),
```

遍历该电容连接的所有网络，取**最大非零值**作为推断工作电压（电容两端电压等于高电位侧对地的差值）。

**自定义映射**优先于内置规则：用户在 UI 中填写的 `NET前缀=电压` 规则先行匹配，若命中则跳过内置规则。

### 6.2 合格判定

```python
derating_ratio = rated_voltage / working_voltage
合格条件：working_voltage ≤ rated_voltage × threshold_pct / 100
```

`threshold_pct` 默认 70，可在 UI 中调整（范围 50%~100%）。

### 6.3 AC 耦合电容识别

**问题**：差分对之间的 AC 耦合电容两端分别连接差分对的正/负端，如果按普通电容推断工作电压，会得出错误结果（差分信号不是直流偏置）。

**识别算法：**

1. 先收集所有差分对（`_collect_diff_pairs`），建立 `(P端网络, N端网络)` 集合
2. 对每个电容，取其所有连接网络
3. 若能找到两个网络分别对应同一差分对的 P 端和 N 端，则标记为"疑似 AC 耦合"

```python
for pos_sfx, neg_sfx in _DIFF_SUFFIX_PAIRS:
    if any(n.endswith(pos_sfx) for n in cap_nets) and \
       any(n.endswith(neg_sfx) for n in cap_nets):
        → 疑似 AC 耦合
```

### 6.4 PG/OD 信号网络处理

**问题**：`PG_12V` 这样的网络名可能被误推断为 12V，但 PG 信号实际电压由外部上拉决定（通常 3.3V 或 1.8V）。

**识别算法：**

对网络名提取**首 token**（按 `_/./空格` 分割的第一个词），与 OD 信号关键词集合比较：

```python
_OD_SKIP_PATTERNS = {
    'PG', 'PGOOD', 'PWRG', 'PWROK', 'PWRFAIL',
    'FAULT', 'ALERT', 'SMBALERT', 'IRQ', 'INT',
    'PRESENT', 'DETECT', 'OC', 'OCD', ...
}

first_token = re.split(r'[_.\s]', net_name.upper())[0]
if first_token in _OD_SKIP_PATTERNS:
    → 标记为 "⚪ PG/OD信号"，不推断电压
```

用首 token 而非全字符串匹配，避免 `P3V3_PG_OK` 被误判（因为首 token 是 P3V3，不是 PG）。

## 7 电阻检查

### 7.1 上拉/下拉/串阻识别

**第一步**：解析电阻值字符串为欧姆数，支持 kΩ、MΩ、mΩ 等单位及科学计数法：

```python
'10k'  → 10000.0
'4.7k' → 4700.0
'100'  → 100.0
'2.2M' → 2200000.0
```

**第二步**：对每个电阻，取其两端连接的网络（`pin1_net`、`pin2_net`），按以下规则分类：

| 类型 | 条件 |
|------|------|
| 上拉 | 一端接电源网络（P3V3/VCC/...），另一端接信号网络 |
| 下拉 | 一端接 GND 网络，另一端接信号网络 |
| 串阻 | 两端均接信号网络（非电源、非 GND） |

电源网络判断与网络拓扑分析一致（正则匹配 VCC/VDD/P\d/VBAT 等）。

### 7.2 重复上拉/下拉检测

建立 `pullups[signal_net] = [list of pull-up resistors]` 字典。若同一信号网络上的上拉数量 ≥ 2，则报告重复上拉。

### 7.3 串阻分压风险检测（双向扫描）

对每个串阻 `R_s`，其两端网络分别为 `NET_A` 和 `NET_B`，**双向**检查：

```
方向1：bias_net = NET_A，affected_net = NET_B
方向2：bias_net = NET_B，affected_net = NET_A
```

若 `bias_net` 上有上拉/下拉电阻 `R_b`，则 `R_s` 和 `R_b` 构成分压网络。

**风险分级**（`串/偏置比 = R_s / R_b`）：

```python
if ratio >= 0.1 and R_b < 1000:   → ❌ 高风险（比例不满足且偏置阻值小）
elif ratio >= 0.1 or R_b < 1000:  → ⚠ 关注
else:                              → ✅ 正常（R_s < R_b/10）
```

**设计依据**：串阻与上拉之比 < 1:10 时，串阻造成的低电平抬升 < 10%，一般不影响逻辑判断。上拉 < 1kΩ 时电流大，串阻影响更敏感。

同时维护 `indirect_pullups[NET_B]`：记录通过串阻间接感受到上拉的信号，用于后续芯片 Pin 总览。

### 7.4 OD/OC 缺少上拉检测

**多证据分级判定**：

| 证据等级 | 来源 |
|---------|------|
| 强证据 | 网络名含 I2C/SDA/SCL/OC_N/FAULT/ALERT/PRESENT/PGD/SMBALERT |
| 弱证据 | 信号网络连接的驱动器引脚数量少于 2（可能是单向驱动） |

只有强证据或强弱证据组合才会报告，单纯弱证据不报告，避免误报。

检查：该信号网络的 `pullups` 字典是否有上拉记录，若无则报告缺少上拉。

## 8 页面解析（pstxsch）

### 8.1 DRAWING 属性提取

最简单的页面获取方式：从 `pstxprt.dat` 的 `DRAWING` 属性中用正则提取 PAGE 编号：

```python
re.search(r'(PAGE\d+)', drawing, re.IGNORECASE)
```

### 8.2 page.csv 精确映射

若提供了项目根目录，工具会在 `sch_1/` 子目录中寻找 `page*.csv` 文件，这些文件记录了逻辑页号到原理图页面真实名称的映射：

```
CSV 示例：
page_id, sheet_name, title
PAGE1,   sch_1/page1.sch,   POWER
PAGE2,   sch_1/page2.sch,   CPU
```

解析 CSV 后建立 `logic_page → real_page_name` 字典，覆盖 DRAWING 属性中的粗糙信息，使页面字段显示更有意义的标题。

## 10 自然排序

标准字符串排序会导致 `C1 < C10 < C100 < C2`，自然排序期望 `C1 < C2 < C10 < C100`。

**实现**：将字符串分解为交替的文本段和数字段，对数字段做整数比较：

```python
def _natural_sort_key(s: str):
    parts = re.split(r'(\d+)', str(s))
    return [int(p) if p.isdigit() else p.lower() for p in parts]
```

示例：`'C10'` → `['C', 10, '']`，`'C2'` → `['C', 2, '']`，比较时 `2 < 10` 正确。

表格列标题排序时，先尝试纯数值排序（适用于"节点数"等纯数字列），失败时回退到自然排序。

## 11 编码健壮性处理

Cadence 在不同操作系统和版本上导出的文件编码不统一，工具采用多编码回退策略：

```python
encodings = ['utf-8-sig', 'utf-8', 'utf-16', 'utf-16-le', 'utf-16-be', 'gb18030', 'gbk']

for enc in encodings:
    try:
        text = raw_bytes.decode(enc)
        break
    except (UnicodeDecodeError, ValueError):
        continue
else:
    # 所有编码失败，使用 errors='replace' 容错读取
    text = raw_bytes.decode('utf-8', errors='replace')
```

`utf-8-sig` 优先（处理 Windows 记事本保存的带 BOM 的 UTF-8）；`gb18030` 兜底（Windows 中文系统默认编码）。
